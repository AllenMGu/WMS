本版包含 71 条 URS、32 条 GxP 风险、25 条 IQ、101 条 OQ 和 12 条 PQ。数量只代表方案覆盖范围；是否充分仍需质量部门结合实际经营范围、配置、数据量和法规适用性批准。

## 2. 执行顺序

1. 质量部门批准 CSV-00 至 CSV-05 和风险评估。
2. 冻结后端、前端、数据库迁移、配置、测试数据与环境基线。
3. 执行 IQ；所有关键安装项合格后才可进入 OQ。
4. 按风险顺序执行 OQ；失败或偏离必须登记，不允许直接覆盖原记录。
5. 由业务关键用户以真实岗位执行 PQ。
6. 单独完成迁移、备份恢复、数据完整性、权限与接口验证。
7. 关闭偏差/CAPA，更新风险评估和 RTM。
8. 完成培训、VSR 和质量放行审批。

## 4. 完整性检查

每次批准或执行批次应保存：

- Git commit SHA、批准记录和目录清单；
- 文件 SHA-256 清单；
- CI 日志、环境快照、数据库 revision、测试输入与输出；
- 页面截图、API 响应、数据库只读查询、审计链验证结果；
- 偏差/CAPA、复测、RTM 更新和最终放行结论。
