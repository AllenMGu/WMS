# CSV-08 性能确认方案（PQ）

## 1. 目的

由经过培训的业务关键用户，在代表性数据、岗位、仓库、网络和业务量下证明系统支持实际预定用途。PQ 不重复单一接口测试，而是验证跨模块数据、职责、时间和库存的一致性。

## 2. 进入条件

- IQ/OQ 已批准完成，关键偏差关闭；
- 生产候选版本和配置冻结；
- 业务 SOP、生效权限矩阵和培训就绪；
- 使用脱敏但具有代表性的供应商、品种、批次、客户、仓库和运输数据；
- 备份、回退、支持、监控和事件响应可用。

## 3. 业务场景

详细行见 `records/pq_test_cases.csv`，至少包含：

1. 首营供应商—品种授权、采购、收货、抽样、验收、批次入库；
2. 多批次 FEFO 销售、拣货、独立复核、发运和签收；
3. 销后退回隔离、独立检验、合格回库和拒收处置；
4. 不合格登记、质量审批、购进退出取消后重建、批准和退供发运；
5. 不合格品批准、执行和独立见证销毁；
6. 质量锁定对销售/发运的阻断及条件满足后的独立解除；
7. 召回目标识别、通知、回收、进展、关闭和锁定保留；
8. 养护异常触发锁定并完成独立复核；
9. 批号盲盘、差异复盘、批准和调整；
10. 承运资质、冷链监测前置、在途异常、签收和独立关闭；
11. 备份、隔离恢复、用户/业务/审计链抽查；
12. 历史归档查询、筛选、导出和源摘要核对。

## 4. 代表性与性能

业务负责人必须说明所选数据为何代表实际经营。至少覆盖：最大常见单据行数、分批收货、两个有效期批次、库存不足、并发用户、跨仓库权限、临近效期、质量锁定和一次受控失败恢复。

## 5. 证据要求

每个场景保存业务单号、参与账号/岗位、操作时间线、关键页面/API、签名记录、审计记录、库存前后值和最终查询/报表。业务用户记录实际观察，独立质量人员确认质量控制，IT 仅提供技术支持而不能代替业务执行结论。

## 6. 接受标准

所有关键场景完成，业务数量守恒、职责分离正确、签名和审计可追踪、无未经批准的手工修数；性能达到批准目标；现场问题均进入偏差/CAPA；业务、质量和系统所有者同意系统适用于预定用途。
