# CSV-13 接口验证与暂缓范围控制

## 1. 当前集成机制

系统使用出站箱保存待发送消息、幂等键、尝试次数、错误和 `PENDING/RETRY/DEAD` 等状态。该机制可在无真实外部平台时进行内部 OQ，但不能证明具体外部接口已完成端到端验证。

## 2. 通用接口验证要求

每个正式接口必须有：批准的接口需求和字段映射、协议/认证/加密、系统所有权、触发点、幂等键、顺序、超时、重试、死信、人工重放、对账、监控、告警、数据保留、安全分类、时间同步、性能、断网补传和灾备方案。

测试至少覆盖：正常、重复、乱序、缺字段、错误代码、超时、连接中断、重试成功、达到死信、修复后重放、上下游数量/状态/批号对账及敏感信息不进入日志。

## 3. 暂缓项

| 接口 | 当前允许验证 | 尚未验证 | 生产控制 |
|---|---|---|---|
| 九州通 | 出站箱幂等/重试/死信内部逻辑 | 正式协议、认证、字段、联调、对账 | 适配器和调度关闭 |
| 温湿度网关 | 设备/分配/读数/告警/锁定内部逻辑 | 实际探头、校准、网关映射、断网补传、外部告警 | 真实接入配置关闭 |
| 药品追溯平台 | 追溯字段和业务阻断 | 码制、采集、核销、上传、补偿、监管对账 | 上报功能关闭 |

## 4. 启用门槛

暂缓项启用前必须：发起批准变更；更新 URS/RA/FS/DS/RTM；批准接口规范；建立测试环境；完成供应商评估；执行 IQ/OQ/PQ、异常恢复、性能和安全测试；培训用户；完成 VSR 和生产放行。不得直接把当前内部 OQ 的结果改为“外部接口已验证”。
