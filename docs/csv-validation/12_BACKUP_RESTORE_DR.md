# CSV-12 备份、恢复与灾难恢复确认

## 1. 备份设计确认

批准并记录：备份频率、类型、执行账号、加密、主副本路径、异地/离线副本、保留期、容量阈值、失败告警、监控责任人和恢复优先级。`/root` 或同机文件仅能作为本机回滚副本，不能宣称为正式异地 GxP 备份。

项目脚本：`scripts/backup-postgres.sh`、`register_backup_evidence.py`、`restore-drill-postgres.sh`、`check-restored-db.py`。正式命令、路径和计划任务必须在 IQ 中记录实际值。

## 2. 每次备份最低证据

- 开始/结束时间、主机、数据库和 revision；
- 命令/作业 ID、退出码、文件大小、格式；
- SHA-256 和 `pg_restore --list` 可读性；
- 异地/离线副本位置及复制校验；
- 成功/失败状态、告警和处置；
- 执行人和独立复核人。

## 3. 隔离恢复演练

1. 选择已独立复核为 `ACCEPTED` 的成功备份。
2. 记录恢复目标、隔离措施、批准的 RTO/RPO 和开始时间。
3. 校验源备份 SHA-256 与清单可读性。
4. 恢复到隔离数据库，禁止覆盖活动库。
5. 确认 Alembic revision；必要升级必须作为独立批准步骤。
6. 核对关键表总数、用户、主数据、业务单据、库存和审计事件。
7. 使用只读查询和应用 API 抽查记录、权限和导出。
8. 执行审计链和电子签名链校验。
9. 记录结束时间、实际 RTO、数据截止点和实际 RPO。
10. 由非执行人复核并记录结论；清理隔离环境按批准程序执行。

## 4. 失败场景

至少演练一次损坏/哈希不符备份的拒绝、目标空间不足或恢复命令失败的处置，以及主备份不可用时从异地副本恢复。不得把“脚本返回 0”作为唯一成功标准。

## 5. 接受标准

备份连续性达到批准目标；文件可读且 SHA 匹配；异地/离线副本真实存在；隔离恢复达到 RTO/RPO；关键数量、业务状态、库存、审计链和权限正确；失败告警被接收并闭环。
