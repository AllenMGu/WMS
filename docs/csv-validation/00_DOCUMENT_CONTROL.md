# CSV-00 文件控制、审批与证据规则

## 1. 文件状态

| 状态 | 含义 | 允许用途 |
|---|---|---|
| DRAFT | 编制中，未经批准 | 评审、修改；不得作为执行依据 |
| APPROVED | 已由规定角色批准 | 可按批准版本执行 |
| EXECUTED | 已完成执行，等待复核 | 不得修改原始结果，只能追加说明 |
| REVIEWED | 执行结果已独立复核 | 可进入总结与放行评估 |
| EFFECTIVE | 已批准生效 | 运行期受控使用 |
| SUPERSEDED | 已由新版替代 | 只读保存，不得继续执行 |

## 2. 文件首页最低元数据

每份批准文件或其审批记录必须包含：文件编号、标题、版本、状态、系统名称、代码/配置/数据库基线、编制人、审核人、批准人、日期、生效日期、替代版本和变更摘要。

本仓库中的 Markdown/CSV 是受控内容源。若企业需 Word/PDF 签批版，导出件必须记录源 commit SHA 和导出文件 SHA-256，且不得在导出后静默修改。

## 3. 审批职责

| 文件类别 | 编制 | 审核 | 批准 |
|---|---|---|---|
| VP、法规评估、风险评估、VSR、放行 | IT/验证人员 | 业务负责人、质量审核人 | 质量负责人 |
| URS、PQ | 业务流程负责人 | IT、质量 | 业务负责人和质量负责人 |
| FS、DS、IQ、OQ | 开发/IT/验证人员 | 独立技术审核人、业务代表 | 质量负责人 |
| 迁移、备份恢复、接口 | IT/数据负责人 | 数据所有者、独立复核人 | 质量负责人 |
| SOP、培训 | 流程负责人 | IT/业务/质量 | 对应 SOP 批准人 |

同一人不得同时作为同一测试的执行人与复核人；涉及配置或代码修改时，实施人不得批准自己的变更。

## 4. 原始数据和证据编号

证据编号格式：`EV-<阶段>-<用例ID>-<序号>`，例如 `EV-OQ-OQ-ES-004-01`。

每条证据索引至少记录：证据编号、测试 ID、生成时间、系统时间与时区、执行环境、生成者、原文件名、媒体类型、SHA-256、受控路径、脱敏说明和复核状态。

证据不得仅以聊天内容、口头确认或无法追踪来源的截图存在。截图应包含可识别页面、业务编号和时间；API/SQL 证据必须保存请求条件与响应；日志必须保留时间范围和主机来源。

## 5. 更正与版本规则

- 已执行记录不得覆盖。更正必须保留原值、新值、更正原因、人员、日期和复核。
- Git 历史是技术版本记录，不等同于质量审批；批准状态必须在审批台账中明确。
- 任何批准后变更均先填写变更评估，确定是否更新 URS/RA/FS/DS/RTM、是否回归或再验证。
- 已在受控环境执行的 Alembic revision 不得修改；修正使用新的前向迁移。
- CSV 行不得删除已执行记录；撤销时将状态改为 `VOID` 并填写理由及关联偏差。

## 6. 命名与目录

执行批次建议存入 `evidence/<YYYYMMDD>-<environment>-<baseline>/`，其下按 `IQ/`、`OQ/`、`PQ/`、`MIGRATION/`、`DR/` 分类。证据目录是否纳入 Git 应由信息安全和数据分类制度决定；不得向公开仓库提交账号、个人信息、客户/供应商敏感信息、连接串、Token、证书私钥或数据库备份。
