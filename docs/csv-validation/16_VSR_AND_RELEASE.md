### 1.3 偏差和残余风险

列出所有偏差、根因、修复 commit、受影响测试、复测、CAPA、残余风险和关闭批准。不得只列未关闭偏差；已关闭偏差也必须可追溯。

### 1.4 结论

结论只能选择：适用于预定用途；附条件适用（列明条件、期限和监控）；不适用/不得放行。结论必须引用 RTM 完整性、风险接受、迁移、恢复、培训和 SOP 状态。

## 2. 生产放行清单

- [ ] 批准文件版本与部署候选基线一致。
- [ ] RTM 中所有关键需求已追踪并通过。
- [ ] Critical/High 偏差为 0 或已按批准规则关闭。
- [ ] 生产数据库备份已校验，回退方案可执行。
- [ ] Alembic 升级、`current`、`check` 和 readiness 通过。
- [ ] 生产账号、岗位、仓库和紧急账号已复核。
- [ ] 秘密、证书、LDAP、CORS、日志和监控配置已批准。
- [ ] 日备份、异地/离线副本、失败告警和恢复演练已生效。
- [ ] SOP、培训、支持和事件升级联系人就绪。
- [ ] 暂缓接口明确关闭且未被业务依赖。
- [ ] 上线后核对项目、观察期和回退判定点已批准。
- [ ] 系统所有者、业务负责人、IT 和质量负责人签署放行。

## 3. 上线后核对

在批准时间窗内核对版本、readiness、登录、角色、关键主数据、代表性查询、审计追加、备份作业、日志/监控和一笔批准的低风险业务。不得在生产进行破坏性负向测试。异常按偏差/事件 SOP 处置。
