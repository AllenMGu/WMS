# CSV-04 用户需求说明（URS）

## 1. 使用规则

每条需求使用唯一 ID，并在 `records/requirements_traceability_matrix.csv` 中追踪到风险、设计、测试和证据。关键性为“关键”的需求未通过时不得放行。

## 2. 通用、身份和数据完整性需求

| ID | 需求 | 关键性 | 接受标准摘要 |
|---|---|---|---|
| URS-GEN-001 | 系统应使用唯一账号识别每名用户。 | 关键 | 账号唯一；操作可追踪到用户快照 |
| URS-GEN-002 | 系统应支持本地或批准的 LDAP 认证。 | 关键 | 模式明确；生产传输符合批准配置 |
| URS-GEN-003 | 登录失败应持久计数并限流/锁定。 | 高 | 达阈值阻断；成功后按设计清除 |
| URS-GEN-004 | 停用用户应立即失去岗位和仓库访问。 | 关键 | 用户、岗位、仓库映射同步回收 |
| URS-GEN-005 | GSP 岗位应有批准依据、复核日和失效期。 | 关键 | 到期自动失效；复核和撤销有审计 |
| URS-GEN-006 | 系统应阻止批准的岗位冲突和记录级自批。 | 关键 | 角色授权及业务审批均后端阻断 |
| URS-GEN-007 | 权限应受仓库范围约束。 | 关键 | 非授权仓库数据/操作不可访问 |
| URS-GEN-008 | 关键状态变更应要求原因并记录前后值。 | 关键 | 审计含 actor/action/entity/reason/before/after/time |
| URS-GEN-009 | 审计记录应只追加并能发现篡改或链断裂。 | 关键 | 无更新/删除入口；链校验返回断点 |
| URS-GEN-010 | 关键审批/驳回应使用电子签名再确认身份。 | 关键 | 密码错误、过期、重放、正文改变均失败 |
| URS-GEN-011 | 电子签名应绑定签署人、含义、动作、对象和请求摘要。 | 关键 | 签名快照完整且可检索验证 |
| URS-GEN-012 | 所有 GxP 时间应来自同步的服务器时间。 | 关键 | NTP 正常；时区明确；事件顺序一致 |
| URS-GEN-013 | 受控记录取消或驳回后不得物理删除历史。 | 关键 | 原单、明细、人员、原因和时间仍可查询 |
| URS-GEN-014 | 列表应支持有界分页、确定性排序和受控过滤。 | 高 | 无遗漏/重复；筛选结果可复现 |
| URS-GEN-015 | 导出/打印应记录模板版本、条件、时间和份号。 | 高 | 输出与查询一致；受控副本可追踪 |

## 3. 主数据、采购、收货和验收需求

| ID | 需求 | 关键性 | 接受标准摘要 |
|---|---|---|---|
| URS-MD-001 | 合作方必须保存类型、许可证、协议及有效期。 | 关键 | 缺少/过期必备证据不能批准或使用 |
| URS-MD-002 | 合作方和其文件须由独立质量人员核验。 | 关键 | 维护人与批准/核验人不同 |
| URS-MD-003 | 药品质量档案应含批准文号、剂型、持有人、储存和追溯要求。 | 关键 | 必填字段完整且独立批准 |
| URS-MD-004 | 供应商只能供应已批准且有效的关联品种。 | 关键 | 创建、审批、收货、验收各节点实时校验 |
| URS-MD-005 | 供应商—品种授权批量导入应原子完成并进入待审。 | 高 | 任一行错误则全部不写入；结果可追踪 |
| URS-PR-001 | 采购单应由采购创建/提交、质量独立批准或驳回。 | 关键 | 非法状态和自批被阻断；签名/审计完整 |
| URS-PR-002 | 收货必须关联有效批准采购单并限制累计数量。 | 关键 | 无单、超量、错误供应商/品种均阻断 |
| URS-PR-003 | 收货不得直接形成可用批号库存。 | 关键 | 验收合格前数量保持待检隔离 |
| URS-PR-004 | 抽样应记录方案、方法、数量、记录号和人员。 | 关键 | 缺少抽样记录不能完成验收 |
| URS-PR-005 | 收货人与验收人必须分离。 | 关键 | 同一账号验收返回拒绝且状态不变 |
| URS-PR-006 | 过期批次在收货和验收放行时均应阻断。 | 关键 | 日期边界按批准时区计算 |
| URS-PR-007 | 只有验收合格数量才能原子写入批号库存。 | 关键 | 合格/拒收数量守恒；失败无半成品 |
| URS-PR-008 | 旧无批号库存入口不得处理 GSP 药品。 | 关键 | 旧路由返回冲突且不修改库存 |

## 4. 库存、销售、发运和运输需求

| ID | 需求 | 关键性 | 接受标准摘要 |
|---|---|---|---|
| URS-INV-001 | 批号库存应记录批号、有效期、数量、预留和质量状态。 | 关键 | 余额可追溯至受控业务来源 |
| URS-INV-002 | 并发操作不得造成负库存、超卖或重复扣减。 | 关键 | 行锁/版本控制；失败整体回滚 |
| URS-INV-003 | 质量锁定应在分配、拣货、复核和发运各节点阻断。 | 关键 | HOLD 批次不能流出 |
| URS-INV-004 | 解除最后一个锁定前应重新核验资质、批次、追溯和效期。 | 关键 | 任一条件不满足则保持 HOLD |
| URS-SA-001 | 销售单应核验购货方资质和经营范围。 | 关键 | 未批准、暂停或过期购货方不能提交/批准 |
| URS-SA-002 | 系统应按 FEFO 分配满足条件的可用批次。 | 关键 | 先分配最早有效期；不足时不部分预留 |
| URS-SA-003 | 销售、拣货、复核、发运应执行规定的职责分离。 | 关键 | 冲突人员无法执行下一步骤 |
| URS-SA-004 | 发运应在同一事务内扣减预留和实际库存。 | 关键 | 数量守恒；重试不重复扣减 |
| URS-TR-001 | 承运商、车辆和驾驶员应具有有效且批准的资质。 | 关键 | 准备和发运前均重新校验 |
| URS-TR-002 | 冷链运输须有生效监测分配。 | 关键 | 缺失分配不得发运 |
| URS-TR-003 | 在途质量异常应进入质量决定并按风险锁定批次。 | 关键 | 未决定前禁止不当签收/关闭 |
| URS-TR-004 | 签收和关闭应有凭证并由独立人员复核。 | 关键 | 签收人不能关闭；电子签名有效 |

## 5. 退货、不合格品、召回、养护和盘点需求

| ID | 需求 | 关键性 | 接受标准摘要 |
|---|---|---|---|
| URS-RT-001 | 销后退回应关联原发运且累计不得超量。 | 关键 | 超量/错误批次阻断 |
| URS-RT-002 | 退回药品应隔离，独立检验合格后才能回到可用库存。 | 关键 | 待检不可销售；数量守恒 |
| URS-NC-001 | 不合格品登记应锁定对应库存并进入独立质量审批。 | 关键 | 登记人不能批准或驳回自己的记录 |
| URS-NC-002 | 销毁应分离批准、执行和见证，并保存证据。 | 关键 | 人员独立；扣减原子；证据完整 |
| URS-NC-003 | 购进退出只能使用已批准的不合格品记录。 | 关键 | 来源、批次、供应商和数量一致 |
| URS-NC-004 | 取消/驳回退出单应保留明细并允许同一 NC 重新发起。 | 关键 | 取消单历史可查；新单可创建 |
| URS-NC-005 | 同一 NC 同时只能关联一个非取消/非驳回退出单。 | 关键 | 并发重复创建返回 409，无半成品 |
| URS-RC-001 | 召回应识别全部相关购货方、发运批次和当前库存。 | 关键 | 目标集合与追溯查询一致 |
| URS-RC-002 | 召回应按级别跟踪通知、回收数量、进展和报告时限。 | 关键 | 时限使用批准工作日历；数量可核对 |
| URS-RC-003 | 召回关闭必须独立复核且不得自动解除质量锁定。 | 关键 | 未通知目标不能关闭；锁定仍有效 |
| URS-RC-004 | 召回演练不得影响真实库存或发送真实通知。 | 高 | 使用真实追溯目标但无业务副作用 |
| URS-MT-001 | 养护计划应独立批准并逐批记录检查。 | 关键 | 异常批次自动锁定；完成需复核 |
| URS-MT-002 | 近效期扫描应使用批准阈值且重复执行幂等。 | 高 | 相同条件不产生重复活动告警 |
| URS-ST-001 | 盘点应支持盲盘并保存批准基线。 | 关键 | 盘点人看不到账面数；基线可追踪 |
| URS-ST-002 | 差异复核、批准和库存调整应职责分离。 | 关键 | 基线后库存变化时调整被阻断 |

## 6. 环境、质量体系、接口和运维需求

| ID | 需求 | 关键性 | 接受标准摘要 |
|---|---|---|---|
| URS-ENV-001 | 设备和监测分配应经独立批准并受校准有效期控制。 | 关键 | 未批准/过期设备不能激活 |
| URS-ENV-002 | 读数应按来源幂等并形成不可变哈希链。 | 关键 | 重复不新增；篡改可检测 |
| URS-ENV-003 | 严重超限或离线应建立告警并锁定相关批次。 | 关键 | 告警、锁定、质量决定关联完整 |
| URS-QS-001 | 质量风险、事件和 CAPA 应有批准状态机和有效性复核。 | 关键 | 未验证有效性不能关闭高风险 CAPA |
| URS-QS-002 | 培训、受控文件和设备校准应保留版本、结果和复核。 | 高 | 无有效培训/校准时按规则限制使用 |
| URS-INT-001 | 外发消息应使用幂等键、重试和死信。 | 关键 | 重复不重复创建；失败可追踪和重放 |
| URS-INT-002 | 暂缓接口未经批准不得在生产启用。 | 关键 | 配置和放行清单明确关闭 |
| URS-OPS-001 | 生产秘密不得进入代码、日志、API 证据或公开仓库。 | 关键 | 启动门禁、泄漏扫描和轮换证据通过 |
| URS-OPS-002 | 数据库结构必须通过批准的 Alembic 前向迁移管理。 | 关键 | 空库/旧库升级、current/check 一致 |
| URS-OPS-003 | 备份应校验、异地/离线保存并由独立人员复核。 | 关键 | 文件可读、SHA 匹配、失败有告警 |
| URS-OPS-004 | 系统应在隔离环境完成恢复演练并核对关键记录。 | 关键 | RTO/RPO 达标；审计链和业务数量正确 |
| URS-MIG-001 | 历史迁移应控制源包、映射、转换、数量、哈希和异常。 | 关键 | 总量/分类/关键字段/权限/可读性通过 |
| URS-MIG-002 | 历史归档应只读并支持授权检索和导出。 | 关键 | 无修改/删除 API；导出与源摘要一致 |
| URS-NFR-001 | 健康检查应报告数据库和 schema revision 一致性。 | 高 | revision 不符时生产 readiness 返回失败 |
| URS-NFR-002 | 关键列表和操作应在批准负载下满足性能标准。 | 高 | 响应时间、吞吐、错误率达到 PQ 批准值 |
| URS-NFR-003 | 单点业务失败后不得遗留部分状态。 | 关键 | 事务回滚；重试可安全继续 |

## 7. 待企业确认

以下不是可留空的长期缺口，必须在批准 URS 前确定：经营范围、冷链/特殊药品/疫苗适用性、法定节假日工作日历、近效期阈值、温湿度阈值、备份保留期、RTO/RPO、日志保留期、批准浏览器、并发/性能目标、电子签名动作清单和正式接口范围。
