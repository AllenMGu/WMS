# CSV-09 历史数据迁移与归档验证

## 1. 原则

迁移必须可重现、可核对、可回退。源数据只读冻结，提取包和映射版本使用 SHA-256 标识；转换程序、异常处置和重跑均受变更控制。总数相等不能单独证明迁移正确。

## 3. 映射规格最低字段

每个字段记录源字段、源类型、目标字段、目标类型、转换规则、默认值、空值规则、代码表、时区、舍入、截断、校验、拒绝条件和批准人。不得用未记录的人工解释替代映射。

## 4. 执行阶段

1. 源系统范围和截止时间批准；停止或控制增量变化。
2. 只读提取并生成文件清单、记录数和 SHA-256。
3. 在隔离环境执行预迁移；生成成功、拒绝、警告和重复清单。
4. 数据所有者核对总数、分类小计、关键字段和随机/风险抽样。
5. 修复映射或源数据必须形成偏差/变更；重新生成版本和哈希。
6. 批准正式迁移，记录开始/结束、执行人、程序版本和日志。
7. 完成目标系统查询、权限、可读性、导出和业务场景测试。
8. 冻结迁移报告、异常清单和源/目标证据；批准旧系统只读/停用。

## 5. 核对规则

- 全量：文件数量、每对象记录总数、唯一键、必填空值、孤儿外键、重复业务编号；
- 金额/数量：按仓库、品种、批次、状态汇总，库存数量与历史流水核对；
- 日期：创建/审批/业务日期的时区和精度，过期/近效期边界；
- 关键抽样：每类至少按风险批准数量，覆盖最长文本、空值、中文、历史状态、取消记录；
- 完整性：源包 SHA、目标摘要、异常/拒绝总数、重跑次数；
- 可用性：授权用户能查询/导出，未授权用户被阻断；
- 归档：`legacy_archive` 无修改/删除接口，独立核对后才能标记接受。

逐项结果填写 `records/data_migration_reconciliation.csv`。

## 6. 回退和重跑

正式切换失败时按批准判定点停止写入，恢复迁移前备份或切回旧系统。回退后核对旧系统可用性和切换窗口内交易。禁止在无证据情况下直接修改生产目标表；任何修数必须有脚本、双人复核、前后值和审计。

## 7. 接受标准

源包和程序版本固定；所有总量/小计匹配或差异经批准；关键字段抽样 100% 正确；无未解释重复、孤儿或截断；权限和可读性通过；异常全部处置；迁移报告由数据所有者、IT 和质量批准。
