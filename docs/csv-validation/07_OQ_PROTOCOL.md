# CSV-07 运行确认方案（OQ）

## 1. 目的

在受控测试环境中证明系统按规格运行，并在正常、异常、边界、越权、并发、重试和故障条件下保护药品质量与电子记录。具体用例见 `records/oq_test_cases.csv`。

## 2. 执行规则

1. 每条用例使用独立可识别测试数据，记录前置状态和数据编号。
2. 严格按步骤执行；任何非预期行为先保存证据，不得边改边继续。
3. 负向测试必须验证 HTTP/页面错误、业务状态未变化、库存未变化、无半成品及审计行为。
4. 涉及电子签名时保存挑战、操作、签名记录和审计事件的关联证据，但不保存口令或完整 Token。
5. 涉及并发时保存两个会话、开始时间、结果、最终数据库状态和锁/版本证据。
6. 涉及时间时记录 NTP 状态、服务器时区和测试前后时间。
7. 每条用例由非执行人复核；实际结果必须描述观察值，不能只写“同预期”。

## 3. 测试数据角色

至少建立相互独立且仅具必要权限的账号：系统管理员、审计员、采购、收货、验收、质量经理、质量复核、销售、拣货、出库复核、发运、退货接收、养护、盘点、仓库保管、仓库经理、运输协调、环境监测。另设停用、岗位过期、无仓库、职责冲突和错误凭据账号。

## 4. 必测领域

| 领域 | 正向 | 负向/边界 | 恢复/并发 |
|---|---|---|---|
| 认证与权限 | 登录、岗位、仓库 | 错密、锁定、停用、过期、越权、自批 | 停用后现有会话 |
| 电子签名 | 批准/驳回 | 无令牌、错密码、过期、重放、跨对象、正文变化 | 业务失败后令牌策略 |
| 主数据/采购 | 批准供应商及品种采购 | 缺文件、过期、暂停、无授权、过期批次 | 审批后资质变化 |
| 收货/验收 | 分批收货、抽样、合格/拒收 | 超量、同人验收、缺抽样、重复记录号 | 事务失败回滚 |
| 库存/销售 | FEFO、预留、拣货、复核、发运 | 质量锁、效期、资质、职责冲突 | 并发不足、重复请求 |
| 退货/不合格 | 隔离、检验、销毁、退供 | 超量、自批、无见证、重复 NC | 取消后重建、并发创建 |
| 召回/养护/盘点 | 完整业务链 | 时限、未通知、异常未处置、基线变化 | 幂等扫描、重复提交 |
| 环境/运输 | 批准设备、读数、签收 | 过期校准、重复读数、严重告警、同人关闭 | 离线与重放 |
| 审计/归档 | 链验证、查询、导出 | 修改、删除、断链、未授权访问 | 并发追加、恢复后验证 |
| 运维/接口 | 备份、恢复、出站箱 | 错哈希、失败备份、死信、未批准接口 | 重试幂等、恢复演练 |

## 5. HTTP 和数据库核验

API 状态码只是一个观察值：401/403 用于认证/权限，409 用于业务冲突，422 用于请求/签名校验。实际接受标准以业务状态、数据库记录、审计和库存共同判断。SQL 只能使用只读账号；任何人工修复 SQL 必须另行变更审批，不能作为正常测试步骤。

## 6. 自动化测试作为辅助证据

执行并保存：测试收集清单、72 个测试函数对应结果、Python/依赖版本、数据库类型、随机种子、开始/结束时间、退出码和 CI URL。必须同时执行 PostgreSQL 迁移/集成作业，不能只用 SQLite 单元测试证明数据库控制。

建议命令：

```bash
ruff check .
python -m compileall app tests
pytest -q
alembic upgrade head
alembic current
alembic check
```

## 7. 接受标准

- 所有 Critical 用例通过；
- 所有 High 用例通过或偏差已关闭并经质量接受；
- 越权、电子签名、审计、锁定、批号库存、迁移和恢复的负向测试不得豁免；
- 无未解释数据变化、无负库存、无重复扣减、无丢失历史、无不可归属记录；
- 自动化和人工结果不一致时以偏差流程调查，不得选择性采用有利结果。
