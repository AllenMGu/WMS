# CSV-10 数据完整性、审计追踪与电子签名专项

## 1. 审计追踪测试

对创建、提交、批准、驳回、取消、质量锁定/解除、库存变化、授权、配置、备份恢复和迁移等代表性操作，验证审计事件包含：用户、动作、实体、原因、服务器时间、来源 IP、before/after 和哈希链字段。

必须执行：

- 并发创建事件后链仍连续；
- 修改任一历史事件副本后链验证返回首个断点；
- 直接 API 无更新/删除审计入口；数据库权限不授予普通应用用户审计修改权；
- 业务事务失败时无孤立状态/库存/签名，审计行为符合设计；
- 按日期、用户、动作和实体查询的结果完整且分页无遗漏；
- 从已验证备份恢复后审计链仍有效。

## 2. 电子签名测试矩阵

| 场景 | 预期 |
|---|---|
| 正确本地密码/LDAP 凭据 | 生成与指定动作、对象、含义和请求摘要绑定的挑战 |
| 错误密码 | 401；不生成可用挑战 |
| 无签名令牌 | 422/授权错误；业务状态不变 |
| 令牌超过 5 分钟 | 拒绝；业务状态不变 |
| 令牌重复使用 | 409；第二次无业务变化 |
| 令牌用于其他记录/动作/含义 | 拒绝 |
| 申请后修改请求正文 | 摘要不符，拒绝 |
| 非签署人使用令牌 | 拒绝 |
| `REJECTION` 含义用于三个质量驳回动作 | 成功时记录含义、人员、时间和理由 |
| 业务规则失败 | 签名消费按设计回滚或保留为明确失败状态，不得形成孤立成功签名 |

## 3. 记录更正与删除

验证所有受控对象没有未审计的物理删除路径。取消/驳回通过状态和原因实现；PR #32 专项必须证明采购单、购进退出单和不合格品驳回的人员/时间/原因仍可查询，购进退出明细在取消后保留。

## 4. 时间完整性

记录 NTP 同步状态、stratum、offset、时区和数据库时间。创建跨多个模块的时间线，确认创建≤提交≤批准≤执行；在系统时间异常或 NTP 失步场景下按批准监控策略告警。不得手工修改时间戳以“修正”测试。

## 5. 数据库和文件完整性

- 外键、唯一、CHECK、非空和索引与模型一致；
- 备份、导出、迁移包、批准附件和受控文件版本保存 SHA-256；
- 受控文件 revision 保存内容引用和 SHA-256；
- 环境读数保存来源幂等键、原始载荷摘要和哈希链；
- 文件存储路径权限、保留和恢复能力必须由部署验证补充。

## 6. 接受标准

代表性关键记录满足 ALCOA+；审计和签名链有效；所有负向签名场景不改变业务；无普通用户可绕过后端权限或更改历史；恢复后仍能检索、验证和解释记录。
