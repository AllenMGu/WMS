# 九州通接口边界

## 原则

九州通接口属于适配器，不得直接写 `stock` 或 `gsp_batch_stock`。内部业务事务先提交，随后在同一事务中写入
`gsp_integration_outbox`；后台发送器按幂等键投递、重试和对账。外部回执也先保存原始报文，再由应用服务验证状态转换。

## 正式开发前需取得的资料

- 测试/生产地址、网络白名单、TLS 与证书要求。
- 鉴权、签名、时间戳、防重放、密钥轮换方式。
- 药品、客户、仓库、批号、单位和状态代码表。
- 订单、发货、入库回执、库存、退货、追溯码等报文规范与示例。
- 同步/异步模式、超时、限流、重试窗口、错误码和补偿规则。
- 幂等字段、业务唯一键、报文版本和变更通知机制。
- 日终对账文件、差异处理、历史重发和人工干预流程。

## 推荐消息类型

| 消息 | 方向 | 内部触发点 |
|---|---|---|
| `PRODUCT_MASTER_CHANGED` | 本系统→九州通 | 药品质量主数据批准后 |
| `PARTNER_QUALIFIED` | 本系统→九州通 | 合作方质量批准后 |
| `PURCHASE_ORDER_RECEIVED` | 九州通→本系统 | 外部采购/配送单通过校验后 |
| `BATCH_ACCEPTED` | 本系统→九州通 | 收货验收放行后 |
| `SHIPMENT_CONFIRMED` | 双向 | 出库复核及外部回执后 |
| `INVENTORY_SNAPSHOT` | 本系统→九州通 | 日终或按约定周期 |
| `RETURN_STATUS_CHANGED` | 双向 | 退货质量判定后 |

## 必测场景

重复报文、乱序回执、超时后成功、部分明细失败、批号不一致、单位换算、过期资质、质量锁定、库存不足、
追溯码重复、签名错误、接口版本变化、断网恢复、历史重放和日终对账差异。
