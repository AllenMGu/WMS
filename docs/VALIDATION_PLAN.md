# CSV / 计算机化系统验证计划

## 最低文件包

| 阶段 | 文件/证据 | 责任建议 |
|---|---|---|
| 立项 | 验证计划 VP、系统清单、系统边界图 | IT 起草，质量批准 |
| 需求 | URS、法规适用性清单、数据完整性要求 | 业务/质量提出，IT澄清 |
| 风险 | 风险评估 RA、关键功能分级 | IT、质量、仓储联合 |
| 设计 | FS、DS、数据字典、接口规范、权限矩阵 | IT/开发 |
| 追溯 | RTM（法规/URS→设计→测试→偏差） | IT维护，质量审核 |
| 确认 | IQ、OQ、PQ 方案/记录、测试证据 | IT执行，业务参与，质量批准 |
| 数据 | 主数据迁移方案、映射、核对、迁移报告 | 业务负责内容，IT执行 |
| 安全 | 账号权限测试、审计追踪测试、备份恢复测试 | IT + 质量见证 |
| 放行 | 偏差/CAPA、验证总结报告、上线批准 | 质量最终批准 |
| 运维 | SOP、培训、变更控制、周期评审、灾备演练 | 各流程责任人 |

## 推荐验证策略

- GSP 阻断规则、批号分配、质量锁定、审计追踪和接口幂等列为高风险关键功能。
- 销后退货隔离、收货/检验职责分离、召回目标完整性、批次锁定和回收数量核对列为高风险关键功能。
- 不合格品处置批准、销毁执行/见证分离、购进退出原批次关联、库存扣减和召回时限列为高风险关键功能。
- 养护计划审批、异常自动锁定、检查/完成复核分离、召回演练目标完整性和完成报告时限列为高风险关键功能。
- 10个工作日基线当前只排除周末；生产放行前必须验证企业批准的法定节假日工作日历及跨年场景。
- `app/gsp/rules.py` 的每条规则至少对应一条正常、一条异常 OQ 用例。
- GitHub Actions 用于持续执行测试和迁移一致性检查；正式验证仍需保存经批准的方案、可追溯测试数据、执行记录、偏差和签字证据。
- PQ 使用企业真实角色和脱敏主数据，走通采购、收货、验收、不合格处置、购进退出、上架、养护、销售、复核、运输、退回和召回。
- 任何失败重试、手工补数或数据修复都必须保留原值、新值、原因、执行人、审批人和时间。
- 上线前执行一次完整恢复演练，证明备份不仅“生成成功”，而且能在目标时间内恢复并核对关键记录。

## 建议放行门槛

1. 所有高风险 URS 已通过测试，未关闭的高风险偏差为 0。
2. 旧的无批号药品出入库接口已关闭或只能处理明确的非药品范围。
3. 权限由质量批准，测试账号、共享账号和离职账号已清理。
4. 日备份连续成功并完成独立恢复验证。
5. 九州通接口完成双向数量、批号、状态和失败报文对账。
6. 业务、仓储、质量、IT 已培训并签署上线检查表。
