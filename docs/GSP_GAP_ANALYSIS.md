# GSP 差距矩阵

基线日期：2026-08-21。第一版按药品批发企业，以及药品生产企业销售、储存和运输环节的共同要求设计；
实际经营范围（冷链、特殊管理药品、委托储运、疫苗等）确认后还需细化。

## 功能与控制差距

| 优先级 | 能力 | 现状 | 本次变化 | 下一步验收标准 |
|---|---|---|---|---|
| P0 | 唯一账号与最小权限 | 仅管理员/操作员；LDAP 首登或批量导入曾可获宽泛权限 | 新增批准岗位白名单、批准依据、岗位互斥、复核/失效日期、过期访问阻断、离职岗位与仓库权限同步回收；移除旧管理员对 GSP 岗位的常态绕过，仅保留首次质量负责人建档；LDAP 新用户不自动分配仓库或 GSP 岗位 | 质量部门批准企业权限矩阵并按周期执行复核；投用验证确认所有实际账号符合矩阵 |
| P0 | 系统配置与秘密 | 数据库/JWT/LDAP 写在源码 | 全部改为外部注入；LDAP 强制受验证的 LDAPS/StartTLS，禁止 API 保存绑定密码；登录按账号/IP持久限流；生产拒绝弱 JWT、缺失秘密来源和版本引用；新增轮换状态机 | 在目标环境接入批准的秘密管理服务，迁移现有值并执行首次双人轮换与回退演练 |
| P0 | 供货方/购货方资质 | 只有自由文本名称 | 新增合作方及必备许可证/协议附件、销售/采购授权人员、独立核验、变更重审和业务时实时效期阻断 | 质量部门确认企业实际必备文件清单并完成首营资料迁移与复核 |
| P0 | 经营品种质量主数据 | 只有条码、名称、规格、价格 | 新增批准文号、剂型、持有人、储存条件、追溯要求、注册批准档案引用和 NMPA/企业核验引用；维护人与批准人分离，变更自动回到待审批 | 迁移现有品种批准档案并由质量部门完成重新核验 |
| P0 | 批号与有效期 | 通用库存无批号 | 新增批号库存完整闭环；GSP 品种禁止旧版无批号修改，并从旧库存、流水、盘点、入出库查询及导出报表中排除 | 业务确认批号库存为唯一正式账务口径并处置旧历史差异 |
| P0 | 收货与验收分离 | 旧入库单提交即增加库存 | 新增采购→质量审批→按单收货→独立抽样→验收→批次库存闭环；抽样保存方案、方法、数量和记录号；打印保存模板版本、唯一份号与用途 | 质量部门批准抽样 SOP、模板版本和受控份号规则 |
| P0 | 质量可疑药品锁定 | 无 | 新增质量锁定/解除，批号库存同步 HOLD；批号分配、拣货、发运准备、出库复核和最终发运全部重新校验 | 用企业偏差/召回/养护场景执行端到端锁定验证 |
| P0 | 审计追踪 | 普通记录可改、可删，无前后值 | 新增哈希链审计及数据库级并发追加锁；覆盖权限、LDAP、旧接口；保存手工/计划校验结果、事件数量、断点和证据引用，并提供定时任务 | 部署环境配置定期任务、失败告警和质量复核流程 |
| P0 | 电子签名 | 关键审批仅记录当前登录人和操作时间，未重新确认身份或绑定签名含义 | 新增本地/LDAP 身份再确认、5 分钟单次挑战、操作/记录/含义/请求摘要绑定、关键接口强制门禁、签署人快照、不可变签名链及独立验签 | 质量部门批准需签署动作清单、签名含义用语和再认证时限；在目标 LDAP 环境完成失败、超时、重放及并发场景验证 |
| P0 | 每日备份与恢复 | 无应用化证据 | 增加自校验备份、异地复制、失败标记、systemd 参考调度；保存备份独立复核和恢复演练审批、RTO/RPO、执行与验证证据 | 在目标环境配置真实异地/离线介质和监控告警，启用定时器并完成首次独立恢复演练 |
| P1 | 出库复核 | 旧出库单提交直接扣库存 | 新增购货方/品种资质审批、FEFO、库存预留、拣货、逐箱包装/追溯码校验、独立复核、电子签名门禁和发运扣减 | 企业批准包装与随货同行单 SOP，并完成现场验证 |
| P1 | 近效期控制 | 无 | 新增电子签名批准阈值、每日自动扫描、养护/预警证据、停销质量锁定和签名关闭；关闭告警不自动解除质量锁定 | 质量部门批准企业阈值并验证定时任务和升级流程 |
| P1 | 温湿度监测 | 无 | 新增校准设备独立审批/重新校准重审、仓库库位与运输任务监测分配、幂等实时采集、温湿度超限与设备离线告警、严重告警批次锁定、偏差/CAPA 质量决定、运输签收阻断和逐监测点 SHA-256 读数链 | 对接企业实际传感器/网关和告警通知渠道，完成布点、映射、校准、断网补传、时钟同步及数据完整性现场验证 |
| P1 | 退货/召回/不合格品 | 仅入库退库 | 新增销后退回隔离与检验、不合格品登记/批准/监督销毁、购进退出；新增批次召回、库存锁定、购货方通知、回收核对、1/3/7 日期限、演练、完成报告及电子签名批准工作日历 | 配置企业实际工作日历；确认监管报送方式与记录保存策略 |
| P1 | 运输与在途 | 无 | 新增承运商必备文件独立核验与变更重审、车辆/驾驶员批准、路线和交接单固化、在途里程碑、异常质量决定/批次锁定、电子签名签收与独立关闭；冷链发运强制实时监测分配，未决温湿度告警阻断签收 | 迁移实际承运商档案并由质量部门复核；在真实移动作业环境验证签收身份再确认 |
| P1 | 养护 | 无 | 新增企业 SOP 驱动计划、独立审批、逐库存检查、异常批次锁定、下次养护日期、独立复核及批准阈值驱动的近效期选取证据 | 对接实际温湿度系统并形成企业批准的周期分析报告 |
| P1 | 药品追溯 | 无 | 批次可强制追溯码 | 明确追溯平台/码制，完成采集、核销、上传、失败补偿 |
| P1 | 九州通对接 | 无 | 出站箱具备确定性幂等、跳锁认领、退避重试、死信和电子签名重放；保持适配器中立 | 按正式接口规范开发适配器并完成联调、对账、重放测试 |
| P1 | 批号库存盘点 | 旧盘点仅按货物/库位且完成后无受控差异审批 | 新增自动范围选取、批号盲盘、库存交易冻结、差异/CAPA、职责分离、受控调整、并发基线和固化哈希打印 | 质量部门批准企业盘点 SOP 并执行现场验证 |

## 当前投用结论

当前版本可以作为 **GSP 开发基础和原型验证环境**，不能直接作为受控生产系统上线。GSP 管理品种
已被旧 `/api/inbound-orders`、`/api/outbound-orders`、`/api/inventory/scan` 及相关查询报表阻断。
目标环境的实际温湿度网关/告警渠道、九州通正式联调、秘密迁移与首次轮换、备份调度/异地介质/告警、首次恢复演练和完整 CSV 验证完成前，
仍不得作为受控生产系统放行。
